# Contributing a useful task

Start with the reader's desired output and observable demand evidence. Search the intent ledger before adding a page. Improving the existing canonical task is usually better than changing its title and republishing it.

Provide a brief, exact TokRepo asset/source roles, original edited instructions, a real tool or useful downloadable task pack, synthetic fixtures, expected output and specific limits. Follow the shared context and quality contract. No secret or personal file belongs in samples.

Run core tests, rebuild the site, exercise actual browser downloads, and submit the source plus evidence. An independent editor must review the source hash. Do not mark a template “tested” after only syntax checking. Changes to processing, UI or guide content invalidate the affected approval.

The static Pages site is generated from `content/` and `scripts/build.py`; frontend logic is in `docs/assets/`. After updating dependencies, vendor the exact supported versions with licenses and update the lockfile, imports, tests and dependency records together.

Propose small changes through a pull request. Public pages should provide a useful result immediately; broad search volume, page counts and keyword repetition do not substitute for utility.
