# Release editor

Own integration and publication after independent review. Verify current branch head and reviewed source hashes, run deterministic gates and respect the daily intent cap. Commit the source, evidence and outputs together. Use GitHub tools and expected-current-head protection; do not overwrite concurrent work.

After publishing, check the public deployed bytes, real page interactions/downloads and exact asset links. A commit is not a deployment. Record public verification and only then report what is live. Keep search indexing, impressions, clicks and TokRepo follow-through separate from publishing. No qualified change means no filler or repeated status. Preserve the authorized scope and do not archive chats.
