# Release requirements

PASS is a decision against the actual page, not a numerical score or a template filled by its author. An independent editor reviews demand fit, practical usefulness, original value, asset combination, factual boundaries, exact CTA URLs and downloadable assets. Each page record names author, reviewer, content SHA256, PASS or BLOCK and concrete unresolved blockers. No self-review; old tool approvals do not approve new recipes.

Release checks build static HTML with one H1, English language, own canonical, crawlable rendered text, internal links, sitemap, real download bytes and UTM destination links. Record current source hash, browser errors, responsive layout and downloads from the actual built release. Preserve legacy tools and licenses. There is no mandatory independent-tool implementation for a recipe.

Published/accessible, verified property, submitted sitemap, indexed, shown in search, clicked and attributed asset use are separate statuses. Never label a source unavailable result as zero, or a site: miss as definitive non-indexing. Account reports stay private. Use observed settled data to prioritize technical fixes, intent/content improvements, title/description experiments, CTA clarity and topics that lead to asset use. Track changes and retest dates.
