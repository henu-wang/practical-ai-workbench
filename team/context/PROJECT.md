# TokRepo search recipe project contract

## Scope and superseded direction

Use the existing public repository `henu-wang/practical-ai-workbench` and its GitHub Pages deployment as a distribution surface for TokRepo recipes. The repository contains original editable task packages, templates, examples, and public content source. It is a coherent open source resource collection, not an obligation to build independent browser tools.

Superseded: earlier contracts requiring a standalone tool product, a new runnable utility for each intent, or separate workbench activation as the primary outcome. Retain historical reviews. Preserve the six legacy tool routes without continuing new tool development as the editorial strategy. Neither old PASS verdicts nor this contract prove that a corrected public release exists.

## Reader journey

`English task query → useful recipe/template → primary TokRepo asset → supported installation/use`

A reader must understand the task and gain a useful next step before a backlink. The page then makes the asset action visible near its opening and after the worked task. It explains what the asset provides, who it is for, and what the complementary asset adds. Never force an unrelated asset into a popular query.

## Four scope pillars

| Pillar | Reader outcome | Deliverable |
| --- | --- | --- |
| Documents and information | Convert, extract, organize, or summarize material | Recipe, sample input/output, extraction schema |
| Data and recurring office work | Clean, transform, reconcile, or prepare structured data | Task package, reusable rules, validation checklist |
| Writing and communication | Produce a specific email, brief, or other useful text | Editable template, filled example, review criteria |
| Content and workflow reuse | Adapt existing material or repeat a well-defined task | Asset combination, handoff recipe, worked example |

These are editorial scope boundaries, not demand claims or publishing quotas.

## Required page structure

1. A task-focused title and direct answer that fit the observed search intent.
2. A short asset panel: primary asset, secondary asset, role of each, prerequisites, and a prominent primary TokRepo link.
3. Useful original steps or an editable task package/template with a realistic fictional example.
4. An expected output and checking method, with accurate installation/use prerequisites and meaningful failure cases.
5. An explanation of how to continue on the primary TokRepo asset and why the secondary asset matters.
6. Exact attributed source links and truthful verification labels.

No mandatory article length, filler FAQ, keyword stuffing, generic “best AI tools” lists, copied tutorials, or empty recipe shells. A useful template and checked example can be the deliverable; executable code is required only when the page promises executable code.

## Public repository essentials

Preserve the source, task packages, examples, build instructions, original-material license, applicable third-party notices, demand packets, canonical intent ledger, and source-bound independent reviews. Keep the home page organized around task recipes and TokRepo actions. A working Pages URL is a publication outcome, not evidence of indexing or traffic.

The publisher may repair this repository's content, links, build, canonical tags, and sitemap within the authorized scope. No TokRepo production code, paid services, or other distribution channels are part of this job.
